Collect Paw: app map

A take-home guide to where things live in the code. It's a snapshot of commit 65cfb87, so it can drift as the code changes.

What the app is

A map-first web app for Ulaanbaatar. People "capture" stray cats and dogs as photo pins. Collect pins are private. SOS pins show on everyone's map until someone marks the animal helped. The app also finds the closest vet, and pet owners can report a lost pet. People nearby get an alert and can send a sighting back to the owner.

Screens

app/: the main screen, capture, lost-pet pages, notifications, and profile. Next.js App Router.

Shared pieces

components/: the map, pin card, collection grid, vet finder, alert pop-up, and sighting card.

Helpers

lib/: distances (geo.ts), photo shrinking, the alert poller, and types.

Database

supabase/schema.sql: the tables and the rules for who can read or change each row. Photos live in the photos bucket.

One action, end to end: a lost-pet alert

An owner reports a lost pet, and within about 30 seconds someone nearby sees a pop-up in the corner.

The owner saves the report

app/lost/new/page.tsx, search async function save

It uploads the photo into the owner's own folder, looks up a street address if a last-seen place was picked, and inserts a row into lost_pets. The database rule "lost_pets: insert own" in supabase/schema.sql makes sure nobody can file a report as someone else.

2

Other phones check every 30 seconds

lib/useAlerts.ts, search fetchAlert; lib/geo.ts, search alertsFor

fetchAlert reads all open reports, then alertsFor keeps the ones within 3 km of you, or with no place at all. It skips your own reports and any you dismissed. The same hook also counts unread sightings for the bell (fetchUnreadCount).

A practice to reuse

When something "isn't working", reproduce it with evidence before changing code.

At the final review, a lost-pet report and a sighting didn't show up. There were three plausible causes: a broken query, an old version of the app, or different data or accounts. Each one was checked directly:

  • The exact queries from the profile and notifications pages were run against the database, and they worked (see scripts/check-sightings.mjs).
  • The real pages were loaded in a browser as a test owner, and the report and sighting both appeared.
  • So the code was fine. The sighting had gone to a leftover test report, and reports only show for the account that filed them.

The investigation also turned up a real bug: the test scripts were leaving test data in the shared database. It was fixed at the source, with cleanUp in scripts/helpers.mjs.

On any project: list the possible causes, test each one in the smallest way that gives a clear yes or no, and change code only once the evidence points there.

Run it again

  1. Copy .env.example to .env.local and fill in the Supabase URL, the publishable key, and the OpenAI key.
  2. Run supabase/schema.sql once in Supabase → SQL Editor.
  3. Run npm install, then npm run dev, and open http://localhost:3000.
